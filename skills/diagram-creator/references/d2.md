# D2

创建或编辑 `.d2` 文件时读取本参考。D2 适合软件系统和架构文档，强调可读声明、自动布局、容器和一致样式；不用于上千节点的大型图数据分析。

## 基本结构

```d2
direction: right

client: 客户端
platform: 平台 {
  api: API 服务
  db: 数据库 {shape: cylinder}
  api -> db: 查询
}

client -> platform.api: HTTPS
```

- 对象标识符表达稳定语义，显示标签与标识符分离。
- 容器表示真实系统、边界或职责域；不要为了排版制造空容器。
- 关系标签说明协议、动作或数据，不重复两端节点名称。
- 使用 `direction` 表达主阅读方向，让布局引擎决定坐标。

## 样式和复用

- 优先使用 D2 的默认主题，只为语义类别增加少量样式。
- 重复样式使用 classes 或单独样式文件，不在每个对象内复制相同属性。
- 多场景、分层或步骤只在用户确有演示需求时使用 composition 能力。
- `vars`、imports 和替换可以提高复用，但简单图不要引入额外抽象。

## 外部资源与安全

D2 支持 imports、图标、图片和链接。默认只引用任务范围内的本地可信文件，不自动拉取远程资源；交付前确认输出环境能够访问所用字体和图片。

## 完整验证

安装 D2 CLI 后，对可信源文件直接渲染 SVG；成功渲染即完成完整语法检查：

```bash
d2 input.d2 preview.svg
```

最终检查自动布局、容器尺寸、边标签和中文字体回退。
