# 投影坐标与地方独立坐标判断

## 证据优先级

按以下顺序判断坐标参考，前一项优先于后一项：

1. 数据生产方提供的正式坐标说明、EPSG 编号或 `.prj`。
2. 中央经线、分带方式、假东/假北、椭球、单位和转换参数。
3. 同名已知图层或公共控制点的坐标对。
4. 坐标范围、位数和大致地理位置等启发式线索。

坐标范围只能排除部分候选项，不能证明唯一坐标系。不得仅凭 Y 值位数给坐标添加三度带或六度带带号。

## 常见类型

| 类型 | 常见数值特征 | 处理方式 |
|---|---|---|
| 地理坐标 | 经度约 `-180..180`、纬度约 `-90..90`，单位为度 | 确认 WGS84、CGCS2000、GCJ02、BD09 等具体定义 |
| 标准高斯-克吕格 | 北坐标通常为数百万米，东坐标常见数十万米；带号形式可能在东坐标前增加两位 | 必须确认中央经线、三度/六度分带及是否含带号 |
| UTM | 北坐标通常为数百万米，东坐标约 `166000..834000` 米 | 必须确认带号和南北半球 |
| 地方独立/工程坐标 | 原点、旋转、尺度和平移由本地工程定义，数值范围无统一规律 | 原值保留并标记为 `LOCAL_CS`；取得参数或控制点后再配准 |

## 成都场景

成都约位于东经 104°。标准高斯-克吕格候选可能涉及三度带中央经线 105°或六度带第 18 带，但这只是地理位置给出的候选，不能直接套用。

如果数据生产方明确回复“成都坐标系”，通常应按成都地方独立坐标或项目工程坐标处理：

- 保留原始 X/Y/Z，不补带号、不交换轴、不平移。
- `.prj` 使用描述性的 `LOCAL_CS["Chengdu City Coordinate System", ...]`，用于说明单位和身份。
- 同一成都坐标系的图层可以相互叠加。
- 与 CGCS2000、WGS84、GCJ02、影像或在线底图叠加前，必须取得官方转换参数或至少足够的公共控制点。

`LOCAL_CS` 只负责标识，不携带到国家坐标系的数学转换关系。因此“能导入 GIS/CAD 软件”和“能准确落在在线地图上”是两个不同结论。

## 输出约定

- Shapefile 使用 `.prj` 标识坐标参考，并用 `.cpg` 声明 DBF 编码。
- DXF/DWG 保留原始几何坐标；复制同名 `.prj` 作为边车说明。
- 完整属性以 Shapefile DBF 为准，CAD 仅保留几何和显式生成的标注。
- 每次转换都记录有效行数、跳过行数、XY/Z 范围和字段映射，并通过重新读取输出进行验证。
- 可交付 DWG 使用 ODA File Converter 审计生成，并执行 DWG→DXF 回转验证；文件头合法或同一开源库能够自读，都不能单独证明通用 CAD 兼容性。
